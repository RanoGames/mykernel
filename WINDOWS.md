# Сборка и запуск на Windows

Нативно (без Linux) собрать такое ядро можно, но там своя возня с
кросс-компилятором под Windows. Поэтому есть два пути — я опишу оба,
но **рекомендую первый**, он проще и надёжнее.

---

## Вариант 1 (рекомендуется): WSL2 — Linux внутри Windows

WSL2 — это полноценное ядро Linux, работающее в Windows. Внутри него
всё будет собираться и запускаться ровно так же, как в обычном Linux,
из основного README.md — никаких отличий и сюрпризов.

### Шаг 1. Установка WSL2

Откройте PowerShell **от имени администратора** и выполните:

```powershell
wsl --install
```

Это поставит WSL2 и дистрибутив Ubuntu по умолчанию. Дальше
компьютер попросит перезагрузиться. После перезагрузки откроется
окно Ubuntu — задайте имя пользователя и пароль (это уже для Linux,
не для Windows).

Если WSL уже был установлен раньше, но версии 1 — обновите:
```powershell
wsl --set-default-version 2
```

### Шаг 2. Установка инструментов внутри Ubuntu (WSL)

Открываете "Ubuntu" из меню Пуск (это терминал Linux) и выполняете:

```bash
sudo apt update
sudo apt install build-essential gcc-multilib grub-pc-bin grub-common xorriso qemu-system-x86
```

### Шаг 3. Копирование проекта в WSL

Проще всего распаковать архив прямо внутри Linux-окружения (не в
Windows-папке) — так избежите проблем с правами доступа и
переносами строк:

```bash
# из домашней папки Linux (~), а не из /mnt/c/...
cp /mnt/c/Users/ВАШ_ПОЛЬЗОВАТЕЛЬ/Downloads/mykernel.zip ~/
cd ~
unzip mykernel.zip
cd mykernel
```
(Windows-диски доступны в WSL по пути `/mnt/c/...`, `/mnt/d/...` и т.д.)

### Шаг 4. Сборка и запуск

Дальше всё как в главном README.md:

```bash
make          # соберёт build/mykernel.bin
make run      # запустит в QEMU
```

QEMU внутри WSL2 умеет открывать графическое окно прямо в Windows
(через WSLg, встроен в современный Windows 10/11) — окно эмулятора
появится как обычное окно на рабочем столе.

Если графическое окно не появляется (старая версия Windows/WSL без
WSLg), запустите QEMU в текстовом режиме, добавив в Makefile
`-nographic` к команде запуска, либо вручную:

```bash
qemu-system-i386 -kernel build/mykernel.bin -nographic
```
(в этом режиме VGA-вывод не покажется, зато можно увидеть текст
через последовательный порт, если добавить в ядро вывод в COM1 —
про это можно поговорить отдельно, когда дойдёте до этого шага)

## Вариант 2: нативно на Windows через MSYS2

Без WSL, полностью в Windows. Чуть более хрупкий путь, но рабочий.

### Шаг 1. Установка MSYS2

Скачайте и установите MSYS2 с официального сайта: https://www.msys2.org/

После установки откройте **"MSYS2 MINGW32"** (именно 32-битную
консоль, не UCRT64 и не MINGW64) из меню Пуск.

### Шаг 2. Установка инструментов

В открывшемся терминале MSYS2:

```bash
pacman -Syu    # обновление базы пакетов (может попросить перезапустить консоль)
pacman -S make mingw-w64-i686-gcc
```

Готового `grub-mkrescue` под Windows нормально не существует, поэтому
в этом варианте ISO-образ и `make run-iso` вы **не соберёте** — но
это не страшно: `make run` (запуск ядра напрямую через QEMU `-kernel`)
работает без GRUB и ISO вообще, и для разработки этого достаточно.

### Шаг 3. Установка QEMU для Windows

Скачайте инсталлятор с https://www.qemu.org/download/#windows
(ссылка на сборки от qemu.weilnetz.de) и установите. Добавьте папку
установки (обычно `C:\Program Files\qemu`) в переменную PATH, либо
запускайте `qemu-system-i386.exe` по полному пути.

### Шаг 4. Сборка

В консоли MSYS2 MINGW32, перейдя в папку проекта (например,
`cd /c/Users/ВАШ_ПОЛЬЗОВАТЕЛЬ/Downloads/mykernel`):

```bash
make
```

Компилятор в MSYS2 (`gcc` внутри MINGW32) по умолчанию собирает
Windows-подобные PE-файлы, а не чистый ELF, поэтому в `Makefile`
может понадобиться явно указать формат вывода. Если сборка выше
ругается на формат объектных файлов, соберите вручную так:

```bash
as --32 src/boot.s -o build/boot.o
gcc -std=gnu99 -ffreestanding -fno-stack-protector -m32 -c src/kernel.c -o build/kernel.o -Wall -Wextra -O2
ld -m elf_i386 -T src/linker.ld -o build/mykernel.bin -nostdlib build/boot.o build/kernel.o
```

Если `ld` в MSYS2 откажется линковать в ELF (некоторые сборки MSYS2
заточены только под PE) — это известное ограничение нативной сборки
на Windows, и в этом случае **проще перейти на Вариант 1 (WSL2)**,
он не имеет таких проблем в принципе.

### Шаг 5. Запуск

```bash
qemu-system-i386 -kernel build/mykernel.bin
```

---

## Итог

Для 95% случаев используйте **Вариант 1 (WSL2)** — это Linux "из
коробки" внутри Windows, весь процесс идентичен основному README.md,
и именно так делает большинство разработчиков ОС на Windows-машинах.
