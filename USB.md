# Запуск на настоящем ПК с флешки

## Важное предупреждение

Запись образа на флешку **удаляет всё содержимое флешки без возможности
восстановления**. Дважды проверяйте, какое устройство указываете —
легко случайно выбрать не ту флешку (или, того хуже, диск компьютера).
Делайте это на тестовой/ненужной флешке.

Также учтите: код в этом проекте учебный, не имеет защиты памяти и
может зависнуть или уйти в перезагрузку — особенно когда начнёте
дописывать свой код с ошибками. На реальном железе это не страшно:
эта инструкция загружает ОС только с флешки и ничего не пишет на
диск компьютера — просто выньте флешку и перезагрузитесь, если
что-то зависло.

## Шаг 1. Собрать ISO-образ

Внутри WSL2/Linux, в папке проекта:

```bash
make iso
```

Получится файл `build/mykernel.iso`. Он уже загрузочный (GRUB внутри
него настроен через `src/grub.cfg`) — это самый обычный bootable ISO,
как образы дистрибутивов Linux.

## Шаг 2. Записать ISO на флешку

### Из Windows

Используйте одну из бесплатных программ:

- **Rufus** (https://rufus.ie/) — рекомендую, самый простой вариант:
  1. Вставьте флешку (минимум 64 МБ, наш ISO крошечный)
  2. Откройте Rufus, в "Device" выберите вашу флешку
  3. В "Boot selection" нажмите SELECT и укажите `mykernel.iso`
     (если из WSL — скопируйте файл в Windows-папку через
     `cp build/mykernel.iso /mnt/c/Users/ВАШ_ПОЛЬЗОВАТЕЛЬ/Desktop/`)
  4. Partition scheme: **MBR**, Target system: **BIOS or UEFI**
  5. Нажмите START

- **balenaEtcher** (https://etcher.balena.io/) — тоже просто:
  выбираете ISO → выбираете флешку → Flash.

### Из Linux (в т.ч. из самого WSL, если видит устройство, либо
из "настоящего" Linux)

Найдите имя устройства флешки (НЕ раздела, а именно всего диска
целиком, например `/dev/sdb`, а не `/dev/sdb1`):

```bash
lsblk
```

Затем (замените `/dev/sdX` на своё устройство — **трижды
проверьте**, что это флешка, а не системный диск):

```bash
sudo dd if=build/mykernel.iso of=/dev/sdX bs=4M status=progress oflag=sync
```

`dd` не выводит прогресс по умолчанию — флаг `status=progress`
специально его показывает, чтобы вы видели, что процесс идёт, а не
завис. По завершении дождитесь, пока команда сама вернёт управление
терминалу (это значит, что данные точно дозаписаны на флешку).

> WSL2 обычно не имеет прямого доступа к USB-устройствам — для
> варианта с `dd` из WSL может понадобиться `usbipd-win`, чтобы
> "прокинуть" флешку в Linux. Проще в этом случае воспользоваться
> Rufus/balenaEtcher из самого Windows.

## Шаг 3. Настроить BIOS для загрузки с флешки

1. Вставьте записанную флешку в реальный ПК.
2. При включении зайдите в Boot Menu (обычно клавиша `F12`, `F11`,
   `Esc` или `F9` сразу после включения — зависит от производителя
   материнской платы/ноутбука) или в BIOS/UEFI Setup (`Del` или `F2`).
3. Выберите загрузку с вашей флешки. Обратите внимание: наш ISO
   собран под **Legacy BIOS boot** (через GRUB в режиме MBR), поэтому
   если в BIOS включён только **Secure Boot / чистый UEFI без
   поддержки Legacy/CSM** — может потребоваться временно включить
   "CSM" (Compatibility Support Module) или отключить Secure Boot в
   настройках BIOS, иначе флешка может не отобразиться в списке
   загрузочных устройств.

## Шаг 4. Что вы увидите

Появится меню GRUB с одним пунктом `MyKernel`, оно тут же (timeout=0
в `grub.cfg`) загрузит ядро — экран очистится, появится `Hello,
World!`, инициализация подсистем, и запустится ваш shell — можно
печатать команды прямо с настоящей клавиатуры реального ПК.

## Как вернуть компьютер к обычной загрузке

Просто выньте флешку и перезагрузите компьютер — на диске компьютера
ничего не менялось, он загрузится как обычно со своей штатной ОС.

## Отладка проблем

- **Флешка не появляется в Boot Menu** — см. про CSM/Secure Boot
  выше; также попробуйте другой USB-порт (иногда порты USB 3.0
  синего цвета работают иначе на старом железе — попробуйте порт
  USB 2.0, если есть).
- **Чёрный экран без надписи GRUB** — возможно, ISO записался
  некорректно; попробуйте перезаписать ещё раз, либо другой
  инструмент (Rufus вместо Etcher или наоборот).
- **Клавиатура не реагирует в shell на реальном ПК** — у нашего
  драйвера клавиатуры очень простая реализация (только базовый
  scan code set 1, только Shift, без поддержки USB-клавиатур без
  "legacy USB support" в BIOS). Если у вас USB-клавиатура и она не
  реагирует — включите в BIOS опцию "Legacy USB Support" /
  "USB Keyboard Support", она обычно включена по умолчанию, но
  проверьте на всякий случай.
