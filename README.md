# MyKernel — минимальное ядро ОС на C (Multiboot / GRUB / QEMU)

Это ядро загружается через **GRUB** по стандарту **Multiboot v1** и
поднимает простую интерактивную командную оболочку (shell) с
поддержкой клавиатуры.

## Состав проекта

```
mykernel/
├── Makefile              # сборка ядра, ISO-образа, запуск в QEMU
├── README.md             # этот файл
├── WINDOWS.md            # сборка и запуск на Windows (через WSL2)
├── USB.md                # запись ISO на флешку и запуск на реальном ПК
├── EXTENDING.md          # как писать свой код, добавлять команды в shell
└── src/
    ├── boot.s             # Multiboot-заголовок, точка входа, стек
    ├── kernel.c            # инициализация всех подсистем ядра
    ├── linker.ld            # linker script: раскладка секций в памяти
    ├── grub.cfg               # конфиг меню GRUB для ISO-образа
    ├── io.h                    # обёртки inb/outb для портов процессора
    ├── vga.h / vga.c            # вывод текста на экран (VGA text mode)
    ├── gdt.h / gdt.c / gdt_flush.s # собственная таблица сегментов (GDT)
    ├── idt.h / idt.c             # таблица прерываний (IDT)
    ├── idt_load.s                 # ассемблерная инструкция lidt
    ├── isr.h / isr.s                # заглушки обработчиков прерываний
    ├── irq.c                         # перемаппинг PIC, диспетчер IRQ
    ├── keyboard.h / keyboard.c        # драйвер PS/2-клавиатуры
    └── shell.h / shell.c               # командная оболочка ядра
```

Ядро настраивает обработку прерываний, поднимает драйвер клавиатуры
и запускает **shell** с простой **файловой системой в оперативной
памяти** и **калькулятором**: `help`, `clear`, `echo`, `about`,
`reboot`, `calc`, `ls`, `pwd`, `cd`, `mkdir`, `touch`, `write`, `cat`,
`rm`. Подробнее о том, как добавлять свои команды и код — в
`EXTENDING.md`.


## 1. Установка инструментов

Проще всего разрабатывать под Linux (можно и в WSL2 на Windows).

### Вариант А — быстрый старт (обычный gcc, без кросс-компиляции)

Makefile умеет собирать ядро даже **без** кросс-компилятора — обычным
`gcc` с флагом `-m32`. Для этого на Debian/Ubuntu нужно поставить
32-битную поддержку:

```bash
sudo apt update
sudo apt install build-essential gcc-multilib grub-pc-bin grub-common xorriso qemu-system-x86
```

Это самый быстрый способ проверить, что всё работает. Из минусов —
теоретически возможны мелкие несовместимости, если версия gcc
генерирует что-то специфичное для Linux, но для такого простого ядра
проблем быть не должно (я уже собрал и проверил именно этот код
локально: линкуется в чистый статический 32-битный ELF без внешних
зависимостей).

### Вариант Б — "правильный" способ (кросс-компилятор i686-elf)

Это классический подход с сайта wiki.osdev.org — кросс-компилятор
никогда не подтягивает ничего из вашей хост-системы (Linux-заголовки,
libc и т.п.), поэтому со временем, когда ядро станет сложнее, будет
меньше сюрпризов.

Кратко (сборка из исходников, занимает 15-30 минут):

```bash
sudo apt install build-essential bison flex libgmp3-dev libmpc-dev libmpfr-dev texinfo libisl-dev

export PREFIX="$HOME/opt/cross"
export TARGET=i686-elf
export PATH="$PREFIX/bin:$PATH"

mkdir -p ~/src && cd ~/src

# binutils
curl -O https://ftp.gnu.org/gnu/binutils/binutils-2.42.tar.gz
tar xf binutils-2.42.tar.gz
mkdir build-binutils && cd build-binutils
../binutils-2.42/configure --target=$TARGET --prefix="$PREFIX" --with-sysroot --disable-nls --disable-werror
make -j$(nproc)
make install
cd ..

# gcc
curl -O https://ftp.gnu.org/gnu/gcc/gcc-13.2.0/gcc-13.2.0.tar.gz
tar xf gcc-13.2.0.tar.gz
mkdir build-gcc && cd build-gcc
../gcc-13.2.0/configure --target=$TARGET --prefix="$PREFIX" --disable-nls --enable-languages=c --without-headers
make -j$(nproc) all-gcc
make -j$(nproc) all-target-libgcc
make install-gcc
make install-target-libgcc
```

После этого добавьте `export PATH="$HOME/opt/cross/bin:$PATH"` в
`~/.bashrc`, и в системе появится `i686-elf-gcc` — Makefile
автоматически обнаружит его и будет использовать вместо обычного gcc
(это приоритетный путь в Makefile).

Также понадобится QEMU и утилиты для ISO:

```bash
sudo apt install qemu-system-x86 grub-pc-bin grub-common xorriso
```

## 2. Сборка

Из корня проекта:

```bash
make          # соберёт build/mykernel.bin
```

Это скомпилирует `boot.s` и `kernel.c`, слинкует их по `linker.ld` и
получит `build/mykernel.bin` — исполняемый файл ядра в формате ELF32
с Multiboot-заголовком.

## 3. Запуск в QEMU

### Быстрый способ — без GRUB и ISO

QEMU умеет сам грузить Multiboot-ядра напрямую флагом `-kernel`,
эмулируя минимальный загрузчик. Это удобно для разработки:

```bash
make run
```

(эквивалент `qemu-system-i386 -kernel build/mykernel.bin`)

Вы должны увидеть чёрный экран с зелёной надписью `Hello, World!` и
ещё парой строк ниже.

### Полный способ — настоящая загрузка через GRUB с ISO

Так вы проверяете именно то, что будет происходить на реальном
загрузочном диске/флешке:

```bash
make run-iso
```

Это выполнит `make iso` (соберёт `build/mykernel.iso` через
`grub-mkrescue`, используя `src/grub.cfg`), а затем запустит QEMU с
этим ISO как виртуальным CD:

```bash
qemu-system-i386 -cdrom build/mykernel.iso
```

Появится меню GRUB с пунктом `MyKernel`, оно автоматически (timeout=0)
загрузит ядро — и вы увидите тот же `Hello, World!`.

### Как выйти из QEMU

Закройте окно QEMU, либо в терминале нажмите `Ctrl+A`, затем `X`
(если запускали с `-nographic`).

## 4. Как это всё работает (коротко)

1. **GRUB** находит в файле ядра Multiboot-заголовок (магическое
   число `0x1BADB002` в первых 8 КБ файла) и понимает, что это ядро
   можно грузить.
2. GRUB переключает процессор в 32-битный защищённый режим,
   настраивает "плоскую" модель сегментов и передаёт управление на
   адрес `_start` из `boot.s`.
3. `boot.s` настраивает стек (в C-коде без стека ничего не заработает)
   и вызывает `kernel_main()` из `kernel.c`.
4. `kernel_main()` пишет напрямую в видеопамять VGA по адресу
   `0xB8000` — это единственный "вывод", доступный сразу после
   загрузки, без каких-либо драйверов.
5. Когда `kernel_main` возвращается, `boot.s` останавливает процессор
   в бесконечном цикле `hlt`/`jmp`.

## 5. Как расширять ядро

Идеи по порядку возрастания сложности (стандартный путь разработки
своей ОС, см. osdev.org):

1. **GDT (Global Descriptor Table)** — настроить свою таблицу
   сегментов вместо той, что временно даёт GRUB.
2. **IDT + обработчики прерываний (ISR)** — научиться ловить
   исключения процессора (деление на 0, page fault и т.д.) и IRQ
   (клавиатура, таймер).
3. **Драйвер клавиатуры** через порт `0x60` и IRQ1 — чтобы можно было
   вводить текст.
4. **PIT (таймер)** через IRQ0 — получить "тики" времени, нужны для
   планировщика задач.
5. **Управление памятью**: physical memory manager (побитовая карта
   свободных страниц) → paging (виртуальная память) → простой
   heap-аллокатор (`kmalloc`).
6. **Многозадачность**: переключение контекста между несколькими
   "потоками" ядра.
7. **Файловая система** и **загрузка программ из initrd/диска**.

Для каждого шага рекомендую сверяться с https://wiki.osdev.org —
это главная база знаний по написанию ОС с нуля, там разобран каждый
из этих пунктов с примерами кода.

## 6. Частые проблемы

- **`grub-mkrescue: command not found`** — поставьте
  `grub-pc-bin grub-common xorriso` (см. раздел 1).
- **`cannot find -lgcc` при линковке** — значит нет 32-битного
  `libgcc` (пакет `gcc-multilib`). Наш Makefile специально это
  обходит и не линкует `-lgcc`, но если вы усложните `kernel.c`
  (например, добавите 64-битную арифметику или `switch` с большим
  числом веток), компилятору может понадобиться `libgcc` — тогда
  либо ставьте `gcc-multilib`, либо переходите на кросс-компилятор
  (вариант Б).
- **QEMU не установлен** — `sudo apt install qemu-system-x86`.
- **Чёрный экран без текста в QEMU** — проверьте, что используете
  именно `qemu-system-i386`/`qemu-system-x86_64` с флагом `-kernel`,
  а не пытаетесь запустить `.bin` как обычную программу.
- **Компьютер/QEMU бесконечно перезагружается** — это называется
  Triple Fault: процессор ловит исключение, обработчик которого сам
  вызывает ещё одно исключение, и в итоге железо аппаратно
  сбрасывается. Частая причина — сломанная GDT/IDT/стек. Если у вас
  такое возникает после того, как вы сами что-то поменяли в коде,
  для диагностики запустите:
  ```bash
  qemu-system-i386 -kernel build/mykernel.bin -d int,cpu_reset -no-reboot -no-shutdown
  ```
  Флаг `-d int` выведет в терминал все прерывания и исключения,
  которые реально происходят внутри QEMU — по последним строчкам
  перед сбросом обычно понятно, что именно сломалось.
