# Как писать свой код в ядре

## Структура проекта после добавления IDT/IRQ/клавиатуры/shell

```
src/
├── boot.s        # Multiboot-заголовок, точка входа, стек
├── kernel.c       # kernel_main() — инициализация всех подсистем по порядку
├── linker.ld       # раскладка секций в памяти
├── grub.cfg          # конфиг GRUB для ISO
│
├── io.h              # обёртки inb/outb для работы с портами процессора
├── vga.h / vga.c      # вывод текста на экран (терминал)
│
├── gdt.h / gdt.c / gdt_flush.s  # собственная таблица сегментов (GDT)
├── idt.h / idt.c       # таблица прерываний (IDT) — регистрация обработчиков
├── idt_load.s            # ассемблерная инструкция lidt
├── isr.h / isr.s           # заглушки обработчиков исключений (0-31) и IRQ (32-47)
├── irq.c                    # перемаппинг PIC, диспетчеризация IRQ в C-обработчики
│
├── keyboard.h / keyboard.c   # драйвер клавиатуры (IRQ1), кладёт символы в буфер
├── fs.h / fs.c                # файловая система в RAM (ls/cd/mkdir/touch/cat/rm)
├── calc.h / calc.c             # калькулятор выражений (+ - * / и скобки)
└── shell.h / shell.c            # командная оболочка — читает строку, выполняет команду
```

Порядок инициализации в `kernel_main()` продуман так, что его нужно
соблюдать: сначала экран, потом IDT, потом исключения и IRQ, потом
драйверы (клавиатура), и только в конце `sti` (разрешить прерывания).
Если разрешить прерывания до того, как IDT настроена — при первом же
прерывании процессор попытается прыгнуть в мусорный адрес и всё сломается.

## Как добавить новую команду в shell

Это самый частый случай "своего кода". Откройте `src/shell.c`,
функцию `execute_command()`, и добавьте ветку:

```c
} else if (str_equals(line, "mycommand")) {
    terminal_writestring("Privet, eto moya komanda!\n");
}
```

Если команде нужен аргумент (как у `echo`), используйте
`str_starts_with()`:

```c
} else if (str_starts_with(line, "greet ")) {
    terminal_writestring("Privet, ");
    terminal_writestring(line + 6); /* +6 — длина "greet " */
    terminal_putchar('\n');
}
```

Пересоберите (`make run`) и проверьте команду в shell.

## Как добавить новый файл с кодом

1. Создайте `src/myfile.c` (и `src/myfile.h`, если нужны объявления
   для других файлов).
2. Откройте `Makefile`, найдите строку:
   ```makefile
   C_SOURCES   = kernel.c vga.c idt.c irq.c keyboard.c shell.c
   ```
   и допишите туда `myfile.c`. Makefile сам подхватит новый файл —
   отдельно ничего прописывать не нужно, есть общее правило сборки
   `.c → .o`.
3. Для нового ассемблерного файла аналогично допишите его в
   `ASM_SOURCES`.
4. `make clean && make` — пересоберётся всё, включая новый файл.

## Как добавить обработчик своего IRQ (например, таймера)

В `irq.c` таймер (IRQ0) и клавиатура (IRQ1) уже подключены к IDT —
осталось только зарегистрировать свою функцию:

```c
#include "isr.h"

static void my_timer_handler(struct registers* regs) {
    (void) regs;
    /* ваш код — вызывается на каждый тик PIT (по умолчанию ~18.2 раза в секунду) */
}

/* где-то в инициализации, например в kernel_main() после irq_install(): */
irq_register_handler(0, my_timer_handler);
```

## Правила программирования "без операционной системы" (freestanding)

Об этом важно помнить, когда пишете свой код:

- **Нет malloc/free** — динамической памяти пока нет вообще (это
  один из следующих шагов развития ОС, см. `README.md` → раздел
  "Как расширять ядро"). Все буферы — статические массивы
  фиксированного размера (как `char line[128]` в shell.c).
- **Нет printf/scanf** и вообще стандартной библиотеки C — все
  строковые функции (`terminal_writestring`, `str_equals`,
  `terminal_write_uint` и т.п.) написаны руками в этом проекте.
  Если нужна новая функция форматирования — пишите её сами по
  аналогии с уже существующими в `vga.c`.
- **Никаких файлов, файловой системы, консоли ОС** — весь ввод-вывод
  идёт напрямую через порты процессора (`io.h`) или память,
  отображённую на устройства (как VGA-буфер 0xB8000).
- **Глобальные переменные, к которым обращается и основной код, и
  обработчик прерывания**, должны быть `volatile` (см.
  `kbd_buffer`/`kbd_head`/`kbd_tail` в `keyboard.c`) — иначе
  компилятор может закэшировать значение в регистре и не заметить,
  что оно изменилось "неожиданно" (из прерывания).

## Файловая система (ls/cd/mkdir/touch/cat/rm/write/pwd)

Реализована в `src/fs.c` — это **RAM-файловая система** (данные живут
в статическом массиве `nodes[]` в оперативной памяти ядра и пропадают
при перезагрузке). Никакого реального диска пока не используется —
это следующий, гораздо более сложный шаг (нужен драйвер ATA/AHCI и
разбор формата вроде FAT). Команды ls/cd/mkdir и т.д. в shell устроены
так, что переход на дисковую ФС в будущем не потребует переписывать
shell.c — только реализацию функций в fs.c.

Устройство простое: все файлы и папки — это один плоский массив
`struct fs_node nodes[FS_MAX_NODES]`, у каждого узла есть индекс
родителя. Чтобы получить "содержимое папки", просто ищем все узлы
с этим родителем — никакого настоящего дерева указателей не нужно.

Лимиты (можно менять в `fs.h`):
- `FS_MAX_NODES` (128) — всего файлов+папок одновременно
- `FS_NAME_MAX` (32) — длина имени файла/папки
- `FS_FILE_MAX` (512) — размер содержимого одного файла

### Как добавить новую команду работы с файлами

По аналогии с уже существующими в `shell.c` — например, команда
`cat`, которая вызывает `fs_read()`:

```c
static void cmd_cat(const char* arg) {
    const char* content;
    size_t len;
    enum fs_result r = fs_read(arg, &content, &len);
    if (r != FS_OK) { print_fs_error(r); return; }
    terminal_writestring(content);
    terminal_putchar('\n');
}
```

Все функции `fs_*()` возвращают `enum fs_result` — проверяйте его и
выводите `fs_strerror()` при ошибке, как это сделано во всех
существующих командах.

## Калькулятор (calc)

Реализован в `src/calc.c` — классический "recursive descent parser"
(рекурсивный разбор по уровням приоритета операций). Поддерживает
`+ - * /`, скобки, унарный минус, целые числа. Используется в shell
как `calc <выражение>`.

### Как добавить новую операцию (например, `%` — остаток от деления)

Откройте `calc.c`, функцию `parse_term()` (там же, где `*` и `/`,
т.к. у `%` такой же приоритет), и добавьте ветку:

```c
} else if (*pr->p == '%') {
    pr->p++;
    long rhs = parse_factor(pr);
    if (rhs == 0) { pr->error = 1; return 0; }
    value %= rhs;
}
```

### Как добавить дробные числа (float)

Это более серьёзное изменение: пришлось бы поменять тип `long` на
`float`/`double` везде в calc.c, переписать разбор чисел в
`parse_factor()`, чтобы он понимал точку (`3.14`), и написать свою
функцию печати чисел с плавающей точкой в vga.c (аналог
`terminal_write_int`, но для float — там придётся отдельно печатать
целую и дробную часть, т.к. простого способа конвертировать float в
строку без libc нет). Если понадобится — обращайтесь, распишу подробно.

## Типичный цикл разработки

```bash
# 1. правите код в src/
# 2. быстрая проверка:
make run
# 3. если что-то падает/зависает — можно посмотреть на реальные
#    инструкции, которые выполняются, флагом -d:
qemu-system-i386 -kernel build/mykernel.bin -d int,cpu_reset -no-reboot
# (флаг -d int покажет в консоли QEMU все прерывания и исключения —
#  очень полезно для отладки IDT/ISR)
```
